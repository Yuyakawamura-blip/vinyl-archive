# 企画メモ：他の収集家が使えるサービスにする（工程01・02）

作成 2026-10-29。[制作指針](development-principles.md)の工程01（コンセプト設計）と工程02（仕様設計の戦略・要件・構造）にあたる。**事実**と**仮説**を分けて書き、未決定事項は確定扱いにしない。

## 決めたこと（作り手の判断、2026-10-29）

- 最初に役立つと言ってもらいたい相手：**中古で買い集める収集家**
- 試してもらう形：**新規登録を一般公開する**
- 協力者：知人の収集家に何人か頼める

## 現状（事実、2026-10-29 本番で確認）

- 利用者は作り手1人。登録136枚（2026-10-15〜10-26）、全件に写真あり。
- 新規登録はSupabase Authで無効。画面にも登録の入口がない（[README](../README.md)）。
- 未ログインでは写真のアップロードとAI解析が動かないため、他の人は手入力の台帳としてしか使えない。
- AI解析の試算費用は、写真読み取りのみ約0.002ドル、相場・曲目の調査（`gemini-3.8-flash`）で1回約0.15ドル。実測は1件ずつ（[原価記録](checks/2026-10-28-ai-research-cost.md)）。
- 解析の回数に上限がない。ログイン済みの利用者は再調査を何度でも起動できる（[セキュリティ記録](checks/2026-10-28-security-static-review.md)）。
- 根拠のある相場は、記録した4回のどれでも得られていない。出典が付くのは調査モデルを切り替えた後の解析だけ。

## 戦略：誰のどの負担を減らすか

**対象者**：レコード店や中古市で日常的に買い、数百枚規模を持つ収集家。

**困る場面（仮説。協力者への聞き取りで確かめる）**

1. 店頭で「これは持っていたか」がすぐに分からず、ダブって買う。
2. 数百枚を台帳にするのが面倒で続かない。手入力やスプレッドシートは1枚ごとに手間がかかる。
3. 持っている盤の曲目や、いまの相場が分からない。

**今の代替手段（仮説）**：記憶、スマホの写真フォルダ、スプレッドシート、Discogs のコレクション機能（英語。盤の特定を自分でする必要がある）。

**提供する価値（仮説）**：ジャケットを撮るだけで台帳ができ、曲目と相場の候補が付く。店頭でも検索して、持っているかどうかを確かめられる。

**成功を何で確かめるか**（工程05で記録する）

- 1枚の登録にかかる時間（手作業との比較）
- AIの候補を確認・修正し、保存まで終えた割合
- 2回目以降の利用機会（次の買い物・整理）に再び使ったか
- 使えなくなった場合の困り度（5段階）と、その理由

**今回扱わないこと**：課金、ネイティブアプリ、外部の分析サービス、盤面の状態評価、売買機能。

## 要件：一般公開の前に必要なもの

優先度 **必須** は公開の条件。**推奨** は公開と並行して進める。

| # | 要件 | 優先度 | 受入条件 |
|---|---|---|---|
| R1 | 利用者ごとのAI解析の上限 | 必須 | 上限をDBで管理し、超えた解析は実行されない。残り回数が画面で分かる。上限の数値は作り手が決める |
| R2 | 新規登録・パスワード再設定 | 必須 | メール確認つきで自分でアカウントを作れる。パスワードを忘れても戻れる |
| R3 | データの扱いの説明 | 必須 | 写真がGoogle（Gemini）に送られること、AIの結果は候補であること、保存するデータ、退会と削除の方法を、登録前に読める |
| R4 | 退会とデータ削除 | 必須 | 利用者が自分でアカウントとレコード・写真を削除できる |
| R5 | セキュリティの残り（工程09） | 必須 | 検証用の利用者A・Bで、他人のレコード・写真・解析が拒否されることを本番で確認。CSPを設定 |
| R6 | 初回の案内 | 必須 | 初めて開いた人が、登録→撮影→解析結果の確認まで、説明を探さずに進める |
| R7 | 店頭で「持っているか」を素早く確かめる | 推奨 | スマホで開いてすぐ検索でき、該当なしも分かる（困る場面1の仮説を確かめてから判断） |
| R8 | 協力者への聞き取りと記録（工程05） | 推奨 | 協力者数・期間・回答数を残し、上の「成功を何で確かめるか」を記録する |

## 構造：利用の流れと失敗時の戻り先

```text
アプリを開く ─→ 説明を読む ─→ 新規登録（メール確認）─→ 空のコレクション
   │                                                     │
   └ 未ログインのまま手入力で試す（AIは使えないと明示）     ↓
                                     撮影・写真選択 → アップロード → 解析待ち
                                                                    ↓
                                 要確認・情報なし → 詳細で確認・修正 → 保存
                                                                    ↓
                                           一覧・検索で再利用（店頭・整理）
```

| 失敗 | 期待する動作 |
|---|---|
| 解析の上限に達した | アップロードと手入力は続けられる。解析は実行せず、上限と次に使える時期を表示する |
| 確認メールが届かない | 再送でき、迷惑メールの確認を案内する |
| 解析エラー | 写真と入力は失わない。自動で再試行し、失敗が続けば手入力で補える |
| 通信断 | 端末に保存し、オンラインに戻ったら同期する（実装済み） |
